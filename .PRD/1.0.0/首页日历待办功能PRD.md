# 1.0.0

## 首页日历待办

> 类型：新增
>
> 来源：[首页日历待办决策](../../docs/首页日历待办决策.md)

### 概述

在首页状态总览下新增“日历待办”卡片，以当月日历直观呈现已排期的待办商单。用户可切换月份、识别今天和有待办的日期，并点击有待办的日期查看当天待办的只读列表，再跳转至待办页统一处理。该功能不改变既有订单数据结构、不引入依赖，原首页“待办商单”预览卡片改为隐藏保留。

### 数据模型 Schema

#### Order（既有订单，仅读取）

| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| `id` | - | string | 是 | - | 商单唯一标识。 |
| `name` | - | string | 是 | - | 弹窗列表展示的项目名称。 |
| `date` | - | datetime-local 字符串 | 否 | 空字符串 | 用于归属自然日；空值或非法值不产生日历标记。 |
| `status` | - | string | 是 | `todo` | 仅值为 `todo` 的订单属于日历待办。 |

#### CalendarViewState（新增，仅内存）

| 字段 | 控件 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|------|--------|------|
| `year` | 上、下月按钮 | number | 是 | 系统当前年 | 当前浏览月的年份，不持久化。 |
| `month` | 上、下月按钮 | number（0-11） | 是 | 系统当前月 | 当前浏览月的月份，不持久化。 |
| `selectedDate` | 日期单元格 | `YYYY-MM-DD` 字符串 / null | 否 | `null` | 当前弹窗查看的日期；仅在点击有待办日期时更新。 |

### 页面交互

- 卡片位于首页的状态总览下方，替代首页可见的“待办商单”预览区域；待结款卡片位置保持不变。
- 卡片标题显示当前浏览年月，并以左右按钮切换月份；切换跨年时年份同步变化。
- 每个日期单元格按订单本地时间的年月日匹配；不可使用 UTC 转换，避免日期偏移。
- 有待办的日期文字使用既有主题绿色 token；同日多笔待办不显示计数或额外徽标。
- 系统当天使用主题绿色背景高亮；若同时有待办，日期文字仍使用主题绿色，以两种样式共同表达两项状态。
- 点击有待办的日期打开弹窗。弹窗重新从当前订单数据筛选，以确保已推进为其他状态的商单不再展示。
- 弹窗内按确定的排序规则展示项目名称与时间；“去待办看看”关闭弹窗并切换至待办页。
- 点击无待办日期、跨月补位日期（如启用）不打开商单列表；遮罩点击和关闭按钮关闭弹窗。

### 已确认验收标准

- 当月内存在一笔有时间的 `todo` 商单时，其日期仅以主题绿色文字标记。
- 同一日期存在多笔 `todo` 商单时，日期格不出现数量；点击后弹窗列出全部符合条件的商单。
- 将某笔商单从 `todo` 推进为 `pending` 后，刷新全部视图时其日期标记消失，弹窗也不再包含该商单。
- `date` 为空的 `todo` 商单不标记任何日期。
- 系统当天始终有主题绿色背景；当天有待办时仍保持待办日期的文字颜色。
- 切换至上个月或下个月后展示对应自然月；刷新页面后重新展示系统当前月。
- 日历待办列表仅展示名称、时间和跳转入口，不提供编辑控件。
- 现有首页待办预览不再可见，待办页、侧栏徽标和原有数据不受影响。

### 待产品确认

以下项尚未由产品确认；实现前应优先确认。如必须按默认建议落地，须在实现记录中明确说明。

| 事项 | 待确认内容 | 建议默认 |
|------|------------|----------|
| 空日期操作 | 无待办日期是否可点击并显示空态弹窗 | 不可点击。 |
| 一周起始日 | 周日或周一作为首列 | 周日，匹配项目现有“周日—周六”文案。 |
| 同日排序 | 弹窗内多笔待办的顺序 | 按时间升序；未提供具体时间的商单排末尾。 |
| 跨月补位日 | 是否显示上月末、下月初日期 | 显示弱化文字以补全周结构，但不可点击。 |

### 扩展性要求

- 沿用 `sanhuo-workbench-v3` 及既有订单字段，不新增或迁移 localStorage key，确保旧订单兼容。
- 日历待办的计算必须由 `data.orders` 和状态机实时派生，不复制存储待办日期或数量。
- 所有订单名称写入 DOM 前继续使用 `esc()` 进行 HTML 转义。
- 新增日期列表、月份切换等交互使用现有 `data-*` 事件委托约定，避免在每次重渲染时逐节点绑定监听。
- 保持原生 HTML/CSS/JS 与零依赖架构；颜色、圆角、阴影、尺寸全部复用 `:root` 设计 token，不硬编码色值。
- 同时验证 390×844 手机画布和桌面居中画布的布局；日历行数为五或六行时不应遮挡底部内容。
- 修改核心资源后必须递增 `sw.js` 的 `CACHE_NAME`，并保持 Network First 缓存策略不变。
